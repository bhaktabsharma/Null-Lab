Fixed
- **`npm install && npm run dev` crashed on a fresh clone** with
  `ERR_MODULE_NOT_FOUND` for `@nulllab/orchestrator/dist/index.js`: the API and the
  test suites import the workspace packages through compiled `dist/` output that a
  plain install never builds (only CI and the Docker image ran `npm run build`
  first). `npm run dev`, `build`, `test:unit`, `test:integration` and `test:e2e` now
  run the new `npm run build:libs` first. A `predev`-style hook was deliberately
  **not** used: `.npmrc` sets `ignore-scripts=true`, which makes npm skip pre/post
  hooks (verified). Guarded by `tests/unit/repo-scripts.test.ts`.
- A missing `.env` made the API exit with only `SESSION_SECRET: Invalid input` while the
  web dev server kept running, which looks like "labs don't start". The error now says to
  run `cp .env.example .env` (`tests/unit/env-config.test.ts`).
- README: removed the stale "20 working labs / 3 families" claim (actual: 80 labs,
  11 families); documented the npm/WSL2 workflow and the new troubleshooting entry.
- **Compose default deployment could not launch or reach any lab.** The
  production image installed with `--omit=dev` but `tsx` (needed by the process
  runtime for every lab) was a dev dependency; labs bound the container's own
  loopback and their ports were not published; Chromium was installed to a
  different path than the runtime user's `PLAYWRIGHT_BROWSERS_PATH`.
- **Docker runtime could not work as written:** ports can't be published from an
  `--internal` network, labs couldn't call back to the control plane, the
  host-side db path leaked into the container, and every launch ran `docker build`.
  Redesigned (see docs/docker-mode.md). Still experimental/unverified on a daemon.
- **Stale labs survived a control-plane crash** and kept serving with valid
  tokens. Process groups + argv-marker reaping on boot now remove them.
- Failed launches leaked a port and left a half-started process; dead targets
  were still reported "running"; stopped/reset instances left their data files.
- `NULLLAB_CHROMIUM_NO_SANDBOX="false"` was parsed as `true`.
- **No CSRF protection** on cookie-authenticated `/api` routes while lab pages
  (which run attacker JS by design) share the machine. Added an Origin guard.
- Coverage matrix labelled plain-HTTP-client verification as "Burp"; relabelled.

Added (Batch 10 — modern / bug-bounty-relevant categories)
- 8 labs covering vulnerability classes common in current real-world bug bounty reports: client-side
  prototype pollution (real headless-browser verification — a naive deep-merge touches
  Object.prototype), password-reset poisoning via a trusted Host header (verified with `node:http`
  directly, since `fetch()` forbids scripts from setting Host, same as a real browser), stored XSS
  via an uploaded SVG inlined into the page (first implementation used <object> embedding, which
  creates an isolated nested document the payload couldn't reach across — caught by the test, fixed
  by inlining the raw SVG markup instead), SSRF to the canonical cloud-metadata address
  169.254.169.254, a JWT lab with a real, correctly-enforced signature whose secret is weak enough
  to recover with a REAL offline HMAC brute force over a short wordlist, second-order SSRF through a
  PDF/report-rendering step that fetches embedded image URLs, a bulk CSV-export endpoint with no
  multi-tenant scoping, and HTTP parameter pollution (an ownership check and a data lookup disagree
  about which repeated query value wins).
- New taxonomy subcategories: `host-header-trust`, `http-parameter-pollution`,
  `ssrf-document-rendering`, `api-version-inconsistency` (routed to the pre-existing
  `modern-platform` and `xml-parsers` families for prototype pollution and SVG parsing, rather than
  inventing redundant subcategories where the taxonomy already anticipated the category).
- **Explicitly out of scope, with a reason:** subdomain takeover. It requires actually controlling
  a dangling DNS record pointed at a deprovisioned real service — there is no way to build it as a
  self-contained local lab without either faking the DNS layer entirely (which teaches nothing real
  about the vulnerability) or touching real external DNS (unsafe and outside what this platform can
  offer). Noted here rather than silently skipped, since it's one of the most-reported categories in
  real programs.

Added (Batch 9 — API security)
- 9 API-security labs: excessive data exposure via an unfiltered API response, a brute-forceable
  API key with no rate limit (real exhaustive search in its test), API-specific mass assignment on
  order creation, a deprecated API version that kept an old IDOR the current version fixed,

  hidden mutation) on the real `graphql` package, and a cross-site WebSocket hijacking lab on real
  `ws` / `@fastify/websocket` servers, verified with an actual WebSocket handshake carrying a
  forged Origin header.
- New pinned dependencies: `graphql@17.0.2`, `ws@8.22.0`, `@fastify/websocket@11.3.4`.
- New taxonomy subcategory: `api-version-inconsistency`.

Added (Batch 8 — business logic & races)
- 8 business-logic labs: insecure deserialization via a trusted-type registry reaching an internal
  type, mass assignment via an unfiltered field merge, two distinct price-manipulation labs
  (unchecked negative quantity; client-trusted unit price), a payment-step workflow bypass, and
  three genuine RACE CONDITIONS (single-use coupon redeemed twice, gift-card overdraft, inventory
  oversell) — each verified with a REAL concurrent burst of requests (`Promise.all`) against the
  live target, not a simulated race. Each race lab also confirms a correctly-refused SEQUENTIAL
  retry does not solve it, so the test proves the concurrency itself is what matters.

Added (Batch 7 — file handling)
- 6 file-handling labs: classic path traversal, a URL-encoded/double-encoded traversal bypass of a
  literal-string filter, local file inclusion via an unchecked template path, an upload filter
  bypassed by a double extension, zip-slip (unsafe archive extraction escaping its destination
  directory), and a leftover backup file served as raw source.
- New lab-sdk module `mini-vfs.ts`: a fully simulated filesystem for every file-handling lab, for
  the same reason as the SSRF network simulation — `process` mode has no filesystem sandbox, so a
  lab that actually opened files named by attacker input would make the platform itself
  exploitable. Uses `node:path`'s `posix` helpers (pure string math, no I/O) for real traversal-
  normalization behavior with zero real file access.

Added (Batch 6 — SSRF)
- 6 SSRF labs: basic fetch-and-display, allowlist bypassed via a substring check on the whole URL
  string, a blocklist bypassed via alternate IPv4 encodings (decimal/hex), a genuinely blind SSRF
  proven through an out-of-band side effect rather than response content, webhook-destination abuse
  carrying a synthetic signing secret, and an allowlist bypassed by following an unvalidated
  redirect.
- New lab-sdk module `mock-internal-net.ts`: a fully simulated network for every SSRF lab. It
  parses URLs with Node's own `URL` class (string canonicalization only) and resolves requests
  against an in-memory table the lab defines — there is no code path to a real socket, DNS lookup,
  the public internet, cloud metadata, or the host machine, in any runtime mode. This matters
  because `process` mode (the default) has no network sandbox of its own; see SECURITY.md.

Added (Batch 5 — auth-session)
- 9 authentication/session labs: predictable password-reset tokens, session fixation, logout
  that never invalidates the server-side session, JWT "alg:none" acceptance, an MFA step that can
  be skipped by going straight to the post-login page, username enumeration via differing login
  errors, OAuth redirect_uri validated with a prefix/substring check (local mock identity
  provider, no real network), a predictable "remember me" token derived from the username, and a
  login endpoint with no rate limit or lockout at all (verified with a REAL exhaustive brute force
  against the live target). New lab-sdk helper: a minimal, honest HS256 JWT sign/decode module —
  each lab writes its own deliberately-flawed verify() so the flaw lives in the lab, not hidden in
  shared code.

Added (Batch 4 — client-side)
- 4 client-side labs: xss-dom-hash-sink, open-redirect-login-next, cors-reflect-credentials,
  clickjack-admin-action. Generalized the admin-bot: any page it visits with a `[data-ck-target]`
  element now gets a REAL pointer click (page.mouse.click at actual screen coordinates) at that
  element's position — reusable for any future clickjacking lab, zero changes needed to existing
  XSS labs. Config fix: API rate limit (300/min) is now `API_RATE_LIMIT_MAX`, not hard-coded, so
  test suites that exercise many labs can run without weakening the production default.
- csrf and postmessage-origin (family C) are DESIGNED, not yet implemented: both need a lab to
  reach a second origin (a real attacker/exploit server), which the runtime does not support yet.
  Tracked for a future batch as a generalized "satellite server" extension to the lab-sdk and
  orchestrator, rather than faked with a same-origin stand-in.
